# SKU_Management.md

## Purpose
To provide frameworks for SKU-level management.

## Core Philosophy
**Price and demand are not uniform across SKUs.**

- Black sells more than pink
- Medium sells more than extra large
- Price should reflect demand
- Don't run out of core SKUs

## Principles

### 1. Demand Is Not Uniform
- Black t-shirt > Pink t-shirt
- Medium > Extra Large
- Price should reflect demand
- Nike.com: Bright pink costs less than black

### 2. The Inventory Mismatch Problem
- Core colors/sizes sell out
- Ad account tanks (inventory unavailable)
- Meta thinks the ad sucks
- You had a winner, but you ran out

### 3. Meta Doesn't Track Inventory
- It doesn't know you're out of stock
- It just sees conversion rate plummet
- It stops spending on that ad
- You lose a proven winner

### 4. Price to Demand
- If you have extra inventory in a SKU, reduce price
- Let the market dictate the liquidation point
- Every SKU has a price at which it moves
- It's just not the one you listed

## Process

### SKU Management:
```
1. Track sell-through by SKU (color and size)
2. Identify core SKUs (protect)
3. Identify excess inventory (discount)
4. Match ad spend to inventory availability
5. If core SKU is running low, increase efficiency target
6. If excess SKU is sitting, discount or liquidate
7. Never let a winner run out
```

## Decision Framework

```
What Price for This SKU?
  │
  ├─ Core color/size (high demand)
  │   └─ Full price, protect inventory
  │
  ├─ Non-core color/size (medium demand)
  │   └─ Slight discount
  │
  ├─ Excess inventory (low demand)
  │   └─ Heavy discount, liquidate
  │
  └─ Dying inventory (no demand)
      └─ DEEP discount, move it
```

## Rules

**Always:**
- Price to demand
- Protect core SKUs
- Match ad spend to inventory
- Discount excess inventory

**Never:**
- Let core SKUs run out
- Price all SKUs the same
- Ignore SKU-level demand
- Let ads run to out-of-stock SKUs
