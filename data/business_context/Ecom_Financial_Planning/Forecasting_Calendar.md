# Forecasting_Calendar.md

## Purpose
To provide frameworks for building and using a forecasting calendar.

## Core Philosophy
**Every action you take should have an expected outcome.**

- If you can't assign value to an action, why are you doing it?
- The calendar is the single source of truth
- Daily tracking enables early course-correction
- Historical annotations reveal patterns

## Principles

### 1. The Marketing Calendar
- Every email, SMS, paid ad, organic post
- Every product launch, promotion, PR hit
- Every website change
- Everything planned should be mapped out

### 2. Programmatic Annotations
- API endpoints capture every email subject line
- Every Facebook ad, Google campaign
- Map as overlay on data
- Like Google Analytics annotations at scale

### 3. Daily Forecasting
- Force yourself into the habit daily
- Ask: "What do I believe will occur today?"
- Forces team to evaluate expectations
- Identify where you're wrong early

### 4. Two Rhythms
- Someone plans the big moment (June product launch)
- Someone worries about tomorrow
- They can't be the same person

## Process

### Forecasting Calendar Workflow:
```
1. Map all planned actions
2. Assign expected outcomes to each
3. Track daily performance vs expectation
4. If off on day 5, course-correct
5. Annotate what caused performance changes
6. Use patterns to forecast future
7. Repeat
```

## Decision Framework

```
What Should Be on the Calendar?
  │
  ├─ Product launches → Major peaks
  ├─ Promotions → Secondary peaks
  ├─ Emails/SMS → Existing customer revenue
  ├─ Paid ads → New customer acquisition
  ├─ PR/Influencer → Awareness and demand
  └─ Every action → Expected outcome
```

## Rules

**Always:**
- Map every action
- Assign expected outcomes
- Track daily
- Course-correct early

**Never:**
- Take actions without expected outcomes
- Wait until month-end to adjust
- Keep the calendar in one person's head
- Forget to annotate historical events
